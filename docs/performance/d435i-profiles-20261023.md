# D435i profiles and measured CPU performance — 2026-10-23

All 18 actual trials passed: three profiles × capture/SDK alignment × three repeats. The highest advertised and tested 30 FPS profile was RGB 1920×1080 with depth 1280×720. These measurements came from the AMD workstation (Ryzen AI MAX+ PRO 395, 32 logical CPUs), USB 3.2, firmware 5.17.0.10, pyrealsense2/librealsense 2.58.3. They are not fwmini4 measurements.

Each cell is the median across three trials; alignment p95 is the median of trial p95 values, not a pooled quantile. Capture rows have no alignment call (zero in the raw metric). Logical CPU demand is process CPU seconds / steady wall seconds: 1.0 means one logical CPU. CPU includes SDK threads, RGB conversion and metadata instrumentation, so it is not pure alignment-filter cost.

The preregistered protocol used 2 s warmup, 8 s steady capture, seed 20261023 and an SDK frame queue of capacity 1 without a Python callback. The application output queue is distinct from sensor `frames_queue_size=16`; no claim is made that every internal buffer holds one frame. Read-only startup/end option snapshots retain automatic exposure enabled for depth/RGB and reported exposure values 8500/166 in native option units, without assuming a unit conversion. Both independent unique-stream rates are primary. Pair completions divided by the actual elapsed steady window were 29.8541–29.8574/s; the lower value reflects window boundaries and uses a different denominator from unique-frame cadence. Repeated frames do not count toward unique FPS. Every trial recorded zero observed counter gaps, repeats, resets, timestamp-domain changes and completions after the window. This describes observed cohorts, not proof of absence of all hardware loss. Both streams reported `timestamp_domain.global_time`; no capture age is inferred from that clock.

These are CPU SDK capture and depth-to-color alignment results only. They do not measure full perception, ROS, encoding, geometry accuracy or physical-station acceptance. The current native GPU path is limited to 640×480; higher profiles are unsupported there. No GPU timing or GPU qualification follows from this test. No D435i is attached to live fwmini4, so these AMD CPU figures cannot be transferred to it. Pixel storage stayed inside the SDK; only scalar diagnostics were recorded. The run made no actuator, sensor-option or service changes.
