# Resident measured support-plane estimator implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. The supervisor owns commits and native/GPU admission.

**Goal:** Produce the retained complete measured support-plane value and typed failure from resident prepared points, as a prerequisite to the complete native object report and original workshop release.

**Architecture:** A single resident graph selects the capped population, scores the 120 retained proposals, performs the initial weighted fit and eight Huber refits, and computes the final diagnostics before orientation/snap/admission. Only the final compact result crosses the ordinary host boundary. An explicit three-slot lease owner retains its input and all intermediate buffers until completion; this stage alone is never a complete object observation.

**Tech Stack:** Existing C++ Vulkan owner/leases, Slang SPIR-V, NativeFloat64 and explicit SoftwareBinary64, retained Python/NumPy CPU reference.

**Spec:** [Native geometry integration, sections 5–6](2026-10-23-native-geometry-integration.md#5-implement-the-complete-estimator-and-publication-contract) and [full workshop contract](2026-10-22-beginner-vulkan-workshop.md). ## Global constraints

- Preserve complete report schema, types, order, rejection reasons and false qualification/execution flags. Full report tolerance is absolute `1e-9`; calibrated rays/preparation coordinates use `1e-12`. Discrete membership/order/branch outcomes remain exact.
- Retain global row-major stride 8, radius-3 known-hue exclusion, inclusive support ROI and seed-17 selection capped at 2,000 points.
- Population selection and fitting use two separately reset seed-17 RNG streams. Fitting makes 120 successive `choice(valid, 3, replace=False)` calls; strict greater score retains the first winner.
- Use weighted centered SVD semantics and second singular-value threshold `1e-9`, the fixed winning subset, and exactly eight Huber refits with threshold `.003` and denominator floor `1e-12`. No z-regression or box-moment substitute.
- Compute masks/residual metrics before upward orientation and optional board snap. Retain `nz >= .85`, snap `nz >= cos(5 degrees)` and `abs(d) <= .015`; only afterward apply inliers >=30 and fraction >=.35.
- Only fewer-than-30 population and insufficient dominance are cache-recoverable `SupportPlaneUnavailable` outcomes. Degenerate/no-proposal/non-tabletop/invalid-input failures do not unlock cache. Existing complete-report owner retains cache/state commit and original timestamps.
- Dense points, weights, memberships, residuals and sorting/reduction scratch remain device-local. No 2,000-point host copy, analyzer fallback, per-refit CPU feedback, hot allocation, whole-device wait or frame restamping.
- Existing admitted GeometryPreparation bounds/features and producer identity remain binding. Do not claim this closes 720p/1080p geometry admission, source-clock proof, final-report capacity, full performance or physical acceptance.
- A separate performance worker must refine/review the actual data path, benchmark it and add static guards before any GPU execution. Preserve failures; do not relax numerical/physical thresholds.

## Review focus

1. Population cap changes RNG/order: preserve both independent streams at 2000/2001 and the maximum admitted population.
2. Equal-score proposals, nearly collinear points and solver exhaustion: retain earliest winner/rank failure; exhaustion is explicit failure, never an accepted partial plane.
3. Snap would change diagnostics or hide non-tabletop failure: retain pre-snap metrics and orientation-before-dominance order.
4. Source epoch closes or a lease is dropped while work is in flight: no reuse until its actual fence completes, no old result accepted by a new owner.
5. Cold tables or diagnostic readbacks hide runtime costs: report actual shared/three-slot bytes, hot allocations, submissions, barriers and ordinary versus diagnostic transfers separately.

## Architecture rulings

- Start with immutable cold sampling tables generated by the retained NumPy calls for every admitted population, with exact order and source/runtime hashes. Share one table per configuration; do not upload it per frame. At the current G=4800 bound the direct index payload is 25,238,240 bytes before headers. This avoids a second unverified RNG algorithm and runtime count-feedback; the cost is explicit cold memory and poor scaling to larger future ranges. Higher-resolution admission must reassess that cost.
- Candidate algebra is centered weighted tiled QR followed by a resident 3x3 SVD, using the existing binary64 arithmetic. This preserves singular-value rank testing; it is unqualified until the literal helper matches the frozen support cases. It must not silently become a covariance or approximate-fit fallback if parity fails.
- Keep all nine dependent solves resident. Compact CPU solves would still impose nine dependent GPU/host feedback cycles. The ordinary host result is the final plane/status only.
- This plan implements the next required estimator, not a replacement for complete object geometry, commissioning, teaching review, deployment, three physical cycles or main release.
