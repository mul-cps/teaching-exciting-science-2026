# Opt-in private availability repair

`allow_private_availability_repair=false` is a read-only leaf/node boolean. Aggregate launch argument `perception_supervisor_allow_private_availability_repair=false` forwards it through the real default-off supervisor include. Launch availability never enables policy. Historical adoption ACK must be finalized first; existing explicit enable remains required.

This separate route permits an enabled, terminal WARMING supervisor to repair only an authenticated resident `private_source_receipt_gap` / `private_source_stream_lost` fault without a five-second pre-outage token. The original ARMED/history route is preferred and unchanged. A fault's original first-observation clocks can be old; a current original heartbeat receipt, exact current code/calibration/pin and seven publisher GIDs remain mandatory. This feature does not promise recovery from arbitrary hardware, OS, camera, structural, unknown or calibration faults.

The new intent has an unpredictable `repair_id`, shared original `outage_id`, and immutable decision ENTRY monotonic/ROS clocks. ENTRY+2 seconds includes metadata readiness, graph/TF/result access, independent identity, persistence and final coordinator start admission. The start RPC acceptance record is also clipped to ENTRY+2; no hidden two-plus-two extension. Post-entry native evidence uses the existing two advancing Info acquisition path, with original first unique receipts, 250 ms receipt / 500 ms header / 40 ms pairing bounds, exact calibration/profile/frame and optical TF, and independent post-entry DeviceInfo request/completion/serial. Existing native starter cadence remains 200 ms.

Both known consumer source-binding services must return fresh RPC replies naming the existing epoch/generation/pin, strict false `binding_invalidated`, correct schema/evidence origins, and false image/progress/qualification/execution flags. An unavailable or expired source proof is negative availability metadata only. Partial, malformed, future or contradictory numeric evidence is rejected even when unavailable. This is not a health or IMAGE witness; no fresh derived image is required before resetting a permanently latched private worker.

Fault dedup is persisted before collection. The same journal's three attempts/hour and 30-second cooldown apply. Reservation is durably written before the one fixed coordinator start; strict new in-flight origin is `private_availability_repair`, with exact `repair_id` and `outage_id`. Unknown/late dispatch, IO ambiguity, unavailable preflight or structural failure latches with no automatic retry of that fault. Restarted in-flight jobs remain UNKNOWN; no quota or handled UUID is cleared. Disable cancels unreserved volatile preflight; it does not claim cancellation of an accepted job.

The existing 40-second owned coordinator completion path is reused. Adoption still requires the attributable new private generation/reset/artifact, two actual advancing IMAGE witnesses per consumer, current prospective lineage and unchanged context. Success returns to WARMING (or DISABLED if explicitly disabled meanwhile), clears no quota/dedup, and grants no five-second history or physical permission. Fresh raw SDK/DDS image availability remains the coordinator's independent responsibility; fresh Info alone cannot qualify completion. No arm or native camera is restarted or opened by this supervisor.

## Metadata observations

Supervisor status adds `allow_private_availability_repair` and `private_availability_repair`. The latter has schema `so101-private-availability-repair-v1`, origin, repair/outage IDs, original `entry_monotonic`, `entry_ros_ns`, `deadline_monotonic`, state, and always false qualification/execution. Reservation adds original `reserved_monotonic`, `native_preflight` (original witness scalars/pairs), and `binding_metadata` (original RPC completion receipts/context/state, no health claim). Acceptance adds `job_id` and `coordinator_deadline_monotonic`; reset progress adds `producer_generation` / `accepted_reset_id`; completion adds artifact/pin/consumer epochs. Failed/cancelled observations never renew clocks. Policy events include `private_availability_repair_requested` at original ENTRY and `private_availability_repair_reserved`.

Software evidence is recorded separately under `overnight/private-availability-repair/task-B`: real isolated DDS177 uses synthetic source/producer/consumers and the actual coordinator/pinner/supervisor, with one reset, two independent DeviceInfo calls (supervisor and coordinator), two actual synthetic IMAGE-admission responses per consumer, charged quota, shared handled UUID, and disabled restoration. It does not qualify live GPU, camera, actual brick discrimination, physical calibration, or pick/place.
